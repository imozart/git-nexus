# Idiomas (i18n)

O GitNexus tem dois idiomas hoje: **Português (Brasil)**, o idioma-fonte, e **English**. A troca é feita **na hora**, sem recarregar:
pelo seletor ao lado do botão *Comandos*, ou pela paleta (Ctrl+K → "Idioma: …" / "Language: …"). A escolha é lembrada. Na primeira
abertura vale o idioma do sistema (qualquer variante de português → pt-BR; o resto → inglês).

## O que está traduzido

| Área | Estado |
|---|---|
| Abas, janela principal, seletor de idioma | ✔ completo |
| Tela inicial (painel de repositórios) | ✔ completo |
| Diálogo de configurações e preferências de fonte (`settings.*`, `core.settings`, `cmd.settings`, `font.*`, `cmd.font*`, `cmd.ligatures*`) | ✔ completo |
| Paleta de comandos e todos os comandos (globais e do repositório) | ✔ completo (a busca acha por palavras em português e em inglês) |
| Aviso de atualização e instalação da atualização | ✔ completo |
| Staging (lista, diff lado a lado, menus, descarte), Grafo/Histórico, Conflitos | ✔ completo |
| Formulário de commit (política, tipos, segredos) | ✔ completo |
| Ferramentas: Operações, Stash, Arquivo/Blame, Rebase, PRs/MRs e CI, Versão/Changelog | ✔ completo |
| Mensagens de erro e aviso do núcleo (`git-core`), do worker, do processo principal e da validação de commit (`governance-policy`) | ✔ completo, no idioma da interface (veja abaixo) |
| Texto gerado a partir dos commits (notas de release e CHANGELOG) | só português: usa o mesmo núcleo do pipeline de release (`scripts/lib/release-core.mjs`) |
| Saída do próprio `git` (ex.: erro de push) | no idioma que o git usar |

Como as chaves ausentes caem no português, uma tela traduzida pela metade continua funcionando: cada texto aparece no idioma que existir.

## Mensagens do núcleo (erros e avisos)

O `git-core`, o worker e o processo principal não usam o catálogo do renderer: o núcleo tem o **próprio dicionário por chave e por idioma**, tipado, em `packages/git-core/src/messages/` (`pt-BR.ts` é a fonte da verdade e `en.ts` a tradução; o que faltar cai no português, como no renderer):

```ts
tm('lfs.downloaded', { pointers: 3 })   // texto no idioma atual; plural: "um arquivo|{n} arquivos" com a variável n
```

O idioma é o do último `setLocale`: a interface chama `api.setLocale(idioma)` ao iniciar e a cada troca, e o processo principal repassa ao worker (variantes como `en-GB` resolvem para `en`; idioma sem dicionário usa o português). A validação de commit roda no `preload` (outro contexto), então recebe o idioma como argumento (`validateCommitMessage(input, policy, locale)`). O padrão continua sendo o português, o que mantém os testes e quem nunca trocou de idioma como antes.

**Migração gradual:** a forma antiga `tm('texto em português', 'English text')` continua funcionando, mas está **depreciada** (só conhece dois idiomas). Cada PR leva um módulo para chave (hoje: `lfs.ts` e `search-run.ts`; o resto está na lista de `packages/git-core/test/messages-keys.test.ts`, que **só encolhe**: um `tm(pt, en)` novo falha o teste). O mesmo teste confere que toda chave usada existe, que não há chave morta e que as traduções têm as mesmas `{variáveis}` e as formas de plural do idioma. Para um idioma novo do núcleo: um arquivo `messages/<id>.ts` e uma linha em `DICTS` (`messages.ts`).

## Como funciona

- `apps/studio/src/entrypoints/renderer/i18n/core.ts`: núcleo puro: o **catálogo único `SUPPORTED_LOCALES`** (código BCP-47, nome nativo, código curto, direção `ltr`/`rtl` e código `Intl`), a normalização do idioma (`pt_BR.UTF-8` → `pt-BR`, qualquer `pt-*` → pt-BR, o resto → inglês), a preferência (`"system"` ou um idioma fixo), busca de chave, `{variáveis}` e plural.
- `pt-BR.ts`: **fonte da verdade**; toda chave nasce aqui. `en.ts`: tradução (parcial é aceito: `Partial<Record<MessageKey, string>>`).
- `index.ts`: `locale` (o que vale agora) e `localePref` (o que a pessoa escolheu: `system` ou um idioma) reativos, os dicionários lidos do catálogo (cada `<id>.ts` da pasta), `lang` e `dir` do `<html>`, e `t(chave, variáveis?)`, usado nos templates (`{{ t('home.title') }}`, `:placeholder="t('home.search')"`) e nos scripts.
- Plural: `"{n} item|{n} itens"` + variável `n` (regra do idioma via `Intl.PluralRules`). As formas vêm na ordem das categorias que o idioma usa para inteiros (`zero`, `one`, `two`, `few`, `many`, `other`): pt e en têm duas (`one`, `other`); russo, polonês e árabe têm mais, e o teste cobra a quantidade certa de formas.
- **Idioma do sistema:** a escolha padrão é "Sistema" (não grava nada): segue o idioma do sistema a cada abertura, e quem escolheu um idioma fixo continua nele (`gitnexus.locale`).
- Datas e números: use `dateLocale.value` em `toLocaleString`.

> Dica: não use `t` como nome de variável de laço (`v-for="t in …"`), porque sombreia a função de tradução.

## Traduzir mais telas

1. Troque cada texto fixo por `t('area.chave')` e acrescente a chave em `pt-BR.ts` (com o texto original) e em `en.ts`.
2. Rode `pnpm test`. O arquivo `apps/studio/test/i18n.test.ts` **falha** se:
   - uma chave usada em `t('…')` não existe no `pt-BR.ts`;
   - uma chave do `pt-BR.ts` não é usada em lugar nenhum (chave morta);
   - o inglês tem uma chave que o português não tem;
   - uma tradução usa `{variáveis}` ou formas de plural diferentes do original;
   - há tradução vazia.

## Adicionar um idioma novo (ex.: espanhol)

É **uma linha no catálogo + um arquivo de dicionário**: não há bandeira (bandeira é país, não idioma), nem registro em `index.ts`, nem lista de ids em outro lugar.

1. Copie `en.ts` para `es.ts` (o nome do arquivo é o código do idioma) e traduza os valores. Pode traduzir só parte: o que faltar cai no português.
2. Em `core.ts`, acrescente uma linha em `SUPPORTED_LOCALES`: `{ id: 'es', label: 'Español', short: 'ES', dir: 'ltr', intl: 'es-ES' }`. `label` é o nome do idioma nele mesmo (não se traduz); `short` é o código mostrado no botão; `dir` é `rtl` para árabe ou hebraico; `intl` é o código usado em datas e números. O tipo `Locale`, o seletor, a validação, os dicionários, o `lang`/`dir` do `<html>` e as datas saem daí.
3. Em `apps/studio/test/locales.test.ts`, acrescente `es` ao `DICTS` (o TypeScript avisa se faltar).
4. Mensagens do núcleo (erros do Git etc.): acrescente `packages/git-core/src/messages/<id>.ts` (copie o `en.ts`) e registre em `DICTS` (`messages.ts`). O que ainda estiver na forma antiga `tm(pt, en)` (veja a lista em `messages-keys.test.ts`) continua em inglês/português até ser migrado para chave.
5. Rode `pnpm test`: `i18n.test.ts` confere chaves e variáveis; `locales.test.ts` confere que o idioma tem código BCP-47 válido, nome, código curto, direção e arquivo de dicionário, e que as traduções com plural têm as formas que o idioma exige (`Intl.PluralRules`).
6. Idiomas da direita para a esquerda (árabe, hebraico): com `dir: 'rtl'` o app já põe `dir="rtl"` no `<html>`, mas a **revisão visual do layout** não vem pronta.
